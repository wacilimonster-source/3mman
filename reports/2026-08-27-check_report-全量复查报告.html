  • 第一层（14 个断链）：删除 PackageManagerWrapper / IBaseAbout / IUpdate / INotice / 4 个重复 Adapter / ProblematicViewPager 时未同步更新引用方：PSVS21、IAbout、UpdatePresenter、NoticePresenter 四处悬空；新拆出的 DownloadEnqueuer 用了不存在的 com.m3man.service.* 包路径；ParseV9MmanVideo 引入工程依赖里没有的 androidx.annotation.WorkerThread。

⚠️ M-09 修复引入了比原问题更严重的功能回归 —— 本轮已确认并修复

findV9MmanItemByViewKey 的"3 查合一"把三个 ViewKey.eq(...) 条件直接塞进同一个 where()。GreenDAO 的可变参数 where() 默认 AND 连接——一个 key 不可能同时等于裸 key、带前缀 key 和原值三种形态，查询恒返回空，且兜底分支犯了同样的错。
影响面：下载主链（DownloadPresenter.validateAndResolveItem 及整条下载流程）、推荐页下载（DownloadEnqueuer）、saveV9MmanItem 的状态合并（mergeDownloadState 继承失效）——相当于"永远查不到已有视频记录"。
修复：按 greenDAO 正确 API 改为 qb.where(qb.or(cond1, cond2, cond3))（已用 javap 对照 greendao-3.2.2.jar 确认 API 存在），主查询与兜底两处同步修正，编译复验通过。
